# 用药提醒（Pill Reminder）

自托管的用药提醒小服务：定时推送到微信，手机打开网页打卡，计划在表格里维护。

只用了 Node 内置模块（含 `node:sqlite`），没有第三方依赖，不用 `npm install`，
也不用编译原生模块，一个容器起来就能用。

> 仓库里不含真实用药数据。计划、打卡记录、推送凭据都放在运行时的 SQLite 文件里，
> 由你在配置页自己录入。

## 功能

| 能力 | 说明 |
|---|---|
| 定时推送 | 每分钟检查一次计划表，到点通过 PushPlus / 企业微信群机器人 / Server 酱 / 自定义 Webhook 推送 |
| 多人接收 | 企业微信群机器人推群里（可 @所有人），或配多个 SendKey 各收各的 |
| 超时催办 | 到点后 N 分钟仍未打卡，再发一条催办；已打卡或该条关了推送就不催 |
| 晚间总结 | 每天固定时间汇总当天完成情况，开关关闭则完全不发；当天无项目时也不发 |
| 每条可关推送 | 计划表里每条单独一个「推送」开关，关掉只不发微信，仍可手动打卡 |
| 打卡页 | 移动端优先，按日期查看待办，点一下即可勾选/取消，显示完成进度与超时标记 |
| 按星期执行 | 每条计划可单独指定周几执行（也支持「每天 / 工作日 / 周末」），非执行日不推送、不出现在打卡页 |
| 周 / 月记录 | 打卡页可切「日 / 周 / 月」：周视图看每天完成度，月视图是日历，都附按项目完成率 |
| 配置表格 | 表格式管理用药计划（时间 / 药品 / 剂量 / 方式 / 备注 / 星期 / 启用 / 推送），整表一键保存 |
| 隐私模式 | 开启后推送正文不含药品名称，只提示「有待办事项」 |
| 推送留档 | 每次推送（含测试、催办）记录结果与失败原因，同一计划同一天同一时间同一类型最多尝试 3 次 |
| 数据导出 | 计划表、打卡记录均可导出 CSV |
| 批量导入 | 粘贴 CSV / 从 Excel 复制 / 选文件，一次导入整张计划表；重复项自动跳过 |
| 管理口令 | 可选。设置后管理接口需口令，打卡接口不受影响 |

## 快速开始

### 方式一：飞牛 FnOS / NAS 部署（推荐）

仓库带两份 compose，按有没有装 WatchCow 二选一：

| 文件 | 用途 |
|---|---|
| `docker-compose.yml` | 标准版。飞牛 Docker「新建项目」直接粘贴，或在目录里 `docker compose up -d` |
| `docker-compose.watchcow.yml` | 装了 WatchCow 的飞牛用它，容器会注册成桌面应用，点开即用 |

镜像由 GitHub Actions 构建并推送到 GHCR，设备上不需要 build：

```
ghcr.io/ac6855/pill-reminder:latest
```

部署完打开：

- 打卡页 `http://NAS_IP:8787/`
- 配置页 `http://NAS_IP:8787/admin.html`

`NAS_IP` 换成 NAS 在局域网中的地址，例如 `192.168.1.20`。

数据落在 `/vol2/1000/Data/pill-reminder/data/app.db`（换机器就改 compose 里那一处路径）。

两点注意：

1. GHCR 在国内经常拉不动，一般不是配置写错。拉不动就把 compose 里的 `image:` 换成
   `pill-reminder:latest`、加一行 `build: .`，再 `docker compose up -d --build`，
   本地构建几秒完成，效果一样。
2. 镜像包当前是 Public，NAS 免登录可拉；若以后改成私有，需在 NAS 上配 GHCR 登录。

### 方式二：WatchCow 应用化（可选）

装了 WatchCow（`github.com/tf4fun/watchcow`）的飞牛，用 `docker-compose.watchcow.yml`，
容器会以「用药提醒」的名字注册成 FnOS 桌面应用。

- 标签名对应 **WatchCow v0.2+**（`display_name` / `desc` / `service_port` / `appname`）
- 图标走本地文件 `file:///vol2/1000/Data/icons/pill-reminder.png`，需先把仓库里的
  `icons/pill-reminder.png` 传到该位置

### 方式三：本地直接跑（适合开发调试）

要求 Node.js **>= 22.5**（`node:sqlite` 自该版本起内置）。

```bash
node app/server.js
# 或指定端口 / 时区
PORT=8787 TZ=Asia/Shanghai node app/server.js
```

其他可选环境变量：

| 变量 | 默认 | 作用 |
|---|---|---|
| `PORT` | `8787` | 监听端口 |
| `TZ` | `Asia/Shanghai` | 推送判定所用时区 |
| `DB_PATH` | `./data/app.db` | SQLite 文件路径 |
| `GRACE_MINUTES` | `5` | 补推窗口（分钟）。服务在该窗口内重启，仍会补发未成功的提醒 |

## 手机上怎么用

打卡页是移动端优先的，手机浏览器直接开 `http://NAS_IP:8787/`。

- **别在微信里打开**。裸 IP 加非标端口的链接，微信内置浏览器多半直接拦成「申请恢复访问」，
  没有「继续访问」的选项。用系统浏览器。
- 添加到主屏幕（推荐）：iPhone 用 Safari → 分享 → 添加到主屏幕；安卓用 Chrome → ⋮ → 添加到主屏幕。
  桌面多一个图标，点开就是浏览器，绕开微信。给家人配好，她自己点图标就行。
- 前提：在路由器里给 NAS 做 DHCP 地址保留（MAC 绑定），否则路由器重启后 IP 变了，链接就失效。
- 异地访问：内网地址在外网打不开，需要内网穿透（如 Tailscale）或飞牛自带远程访问。
  任何映射到公网的做法，务必先在配置页设管理口令，否则管理接口对全网敞开。

## 首次配置

1. 打开配置页 → **用药计划** → 点「+ 新增一行」，逐行填写时间与内容，改完点右上角「保存全部」一次提交
   - 按钮上会显示还有几项没保存，例如「保存全部 · 3 项待保存」
   - 「启用」「推送」的勾选也一并随「保存全部」提交，不再即时生效
   - 新增行若什么都没填，保存时自动丢弃，不算错误
   - 时间格式 24 小时制 `HH:MM`
   - **星期**一列 7 个小按钮，点亮表示当天执行，默认全亮（每天）；只吃工作日的就点亮一~五
   - **启用**管是否执行与计分，**推送**管这条是否发微信，两项互不影响
   - 停用的行不推送、也不计入打卡总数
   - 想先看效果可点 **数据管理 → 载入示例模板**（3 行通用示例，随时可删）
   - 计划条目多时用 **数据管理 → 导入用药计划** 批量录入，见下节
2. 切到 **推送设置**，选择渠道并填凭据：

   **PushPlus（推荐，苹果安卓都能收）**
   - 微信搜索公众号「pushplus 推送加」并关注，发消息「token」，它会回一串 token
   - 在公众号个人中心完成**实名认证**。没实名的账号调接口一律返回 905，一条也发不出去
   - 每人一个 token，用逗号隔开填进同一个输入框
   - 免费 200 条/天，每分钟最多 5 次请求，相同内容 1 小时内最多 3 条

   **企业微信群机器人（都在用企业微信时选它）**
   - 注册一个企业微信（选「团队」，个人也能注册，不需要营业执照），把家人手机号加进通讯录
   - **电脑端**进群 → 右上角「···」→ 群机器人 → 添加 → 复制 Webhook（手机端常常没这个入口）
   - 填到「企业微信 Webhook」，勾选「群内 @所有人」（手机更容易弹提醒），保存
   - 群里所有人都能看到同一条提醒，谁先看到谁去打卡

   **Server 酱（微信，不用建群）**
   - 访问 `https://sctapi.ftqq.com` 微信扫码登录，复制 SendKey（形如 `SCT...`）
   - 想各自收各自的：每人注册一个，几个 SendKey 用逗号隔开填进同一个输入框
   - 最多支持 10 个，全部发送成功才算成功，日志里会显示 `1/2 个 SendKey 成功` 这样的计数
   - ⚠️ **免费额度只有每天 5 条**，一天十几个提醒根本不够用；会员 39 元/年可到 1000 条/天。
     新号注册送 7 天全功能试用，先拿它验证通道是否通畅最省事

   **自定义 Webhook**
   - 任意接收 `POST JSON` 的地址，字段为 `{ title, content, kind, time, name }`，
     `kind` 为 `first`（到点）、`remind`（催办）或 `evening`（晚间总结）

3. 设置「超时催办」分钟数（默认 20，0 = 关闭）；需要每天晚上来一条总结就把「晚间总结」勾上并设时间
4. 点 **发送测试推送** / **发送催办样张** / **发送总结样张** 各发一条，确认手机能收到；再点「保存设置」
5. 建议在推送设置里设置一个**管理口令**（留空则不校验，仅适合完全可信的局域网）

## 批量导入计划

配置页 → **数据管理** → 「导入用药计划」。三种进料方式都行：

1. **直接粘贴**：文本框里每行一条
2. **从 Excel 复制**：选中区域复制，粘贴进来即可（自动按制表符切分）
3. **选 CSV 文件**：读入后先落到文本框，可改完再导（单文件上限 60 KB）

列顺序固定：`时间, 药品/项目, 剂量, 方式, 备注, 启用, 星期, 推送`，后面五列可留空。

```
时间,药品/项目,剂量,方式,备注,启用,星期,推送
07:00,示例药品 A,1 片,口服,早餐前,是,每天,是
08:00,示例药品 B,半片,口服,,是,工作日,是
12:30,示例测量项,,测血糖,,是,周一、周三、周五,否
```

- 首行表头 `时间` / `time` 会自动跳过
- 「星期」一列可写 `每天`、`工作日`、`周末`、`周一、周三`，留空视为每天；
  若只写数字（如 `1,3,5`）必须用英文引号包住整格 `"1,3,5"`，否则逗号会被当成列分隔符
- 「推送」一列写 `否` 表示这条不发微信，留空视为发；老格式（只有 7 列）导入不受影响
- 时间写法宽松：`7:00`、`7点`、`7点30分`、`07：00`（全角冒号）、`700`、`1230` 都会归一成 `HH:MM`
- 已存在的同名同时间计划**不会重复插入**，计入「跳过」而不是报错
- 单次上限 200 行；有失败行时逐条报出行号与原因，成功的行照常写入
- 「替换全部」会先清空现有计划与打卡记录，页面会二次确认

也可以先「导出计划 CSV」拿到模板，填好再导回来，格式天然兼容（星期列导出的就是 `每天` / `周一、周三` 这类可再解析的写法）。

## 推送与催办

**谁会收到**：看渠道。PushPlus 与 Server 酱都是每个 token / SendKey 对应一个人的微信，
配几个就几个人收到；企业微信群机器人把消息发到群里，群里所有人可见。

**什么时候发**：

| 类型 | 触发条件 |
|---|---|
| 到点提醒 | 计划时间到点的那一分钟（含 5 分钟补推窗口），且该条「推送」为开、当天还没打卡 |
| 超时催办 | 到点后 N 分钟（默认 20）仍未打卡，再发一条；只催一次 |
| 晚间总结 | 每天固定时间（默认 21:30）汇总当天完成情况；开关关着就完全不发 |

几个边界情况：

- 已经打过卡就不再推到点提醒。提前吃了药并勾选，到点不会弹。
- 催办不受「到点提醒是否成功」影响：首次推送失败，催办照样按时发。
- 两种类型各自独立计尝试次数，互不占用。
- 跨天也算：23:50 的计划 + 20 分钟 = 次日 00:10 催办，日期仍记在昨天，不会串到新的一天。
- 关掉某条的「推送」后，这条彻底不发消息，到点不发、超时也不催。

调整催办间隔：推送设置 → 「超时催办」，填 0–180 之间的整数分钟；填 0 就是关闭催办。

**晚间总结**：推送设置 → 「晚间总结」勾上，再设一个时间（默认 21:30）。

- 内容形如「今天共 8 项，已完成 6 项，还有 2 项没打卡」，下面逐条列出没打的时间与药名；
  全部完成时标题和正文改成「都完成了」，不再催。
- 打开隐私模式后只报数量，不列药名。
- 开关关掉就一条都不发；开着但当天没有要执行的项目（全部停用或都按星期休息）也不发，
  不会出现「今天 0 项」这种没用的消息。
- 要改时间就改那个时间框；清空会回落到 21:30。
- 不放心可以先点「发送总结样张」，当天有计划就用真实数据、没有就用示例，看手机收成什么样。

## 周记录与月记录

打卡页顶部有「日 / 周 / 月」三个切换：

- 日：当天待办清单，点一下打卡；左右箭头翻前一天 / 后一天。
- 周：一周 7 天各一行进度条，上方是「全勤天数 / 完成项数 / 完成率」，下方按项目列出本周完成率。
- 月：日历形式，每格按当天完成情况着色，深绿=全部完成、浅绿=部分完成、浅红=一项未打、
  灰=当天无计划、虚线=未来。下方同样是汇总与按项目统计。

点周 / 月视图里的任意一天（包括未来日期）会跳到那天的日视图，可以查看安排或补打卡。

统计口径：

- 只算「已启用」的计划；停用的、以及按星期设置当天不执行的，都不进分母。
- 未来日期不计入汇总，所以周中查看时，完成率是按已经过去的天数算的。
- 全勤天数 = 当天所有应执行项目全部完成的天数。

## 数据与隐私

- 全部数据在 `data/app.db`（SQLite，WAL 模式）。备份就是复制这个文件；迁移就连同文件一起搬走。
- 代码里没有真实药品、剂量或个人信息，示例模板也是通用占位。
- 读设置接口不回传凭据明文：SendKey 与管理口令一律返回掩码，页面保存时未改动则保持原值。
- 清空所有数据：配置页 → 数据管理 → 清空全部数据。SQLite 文件本身会保留（体积不会立刻变小）。
- 建议把打卡页和管理页限制在内网。若要暴露到公网，请在前面加一层反向代理并启用 HTTPS，
  同时设好管理口令。

## 接口一览

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/health` | 否 | 健康检查，返回当前日期与时间 |
| GET | `/api/day?date=YYYY-MM-DD` | 否 | 某天的计划与打卡状态（默认今天），只返回当天应执行的计划 |
| GET | `/api/range?from=YYYY-MM-DD&to=YYYY-MM-DD` | 否 | 区间统计，周记录 / 月记录用；跨度上限 62 天 |
| POST | `/api/checkin` | 否 | 打卡：`{ planId, date?, done }` |
| GET | `/api/plans` | 是 | 计划列表 |
| POST | `/api/plans` | 是 | 新增计划 |
| POST | `/api/plans/import` | 是 | 批量导入：`{ mode: "append"\|"replace", items: [...] }`，返回新增/跳过/失败明细 |
| PUT | `/api/plans/:id` | 是 | 更新计划 |
| PATCH | `/api/plans/:id/enabled` | 是 | 启用 / 停用 |
| PATCH | `/api/plans/:id/push` | 是 | 单独开关某条的推送：`{ push_on: true\|false }` |
| DELETE | `/api/plans/:id` | 是 | 删除计划及其打卡记录 |
| GET/PUT | `/api/settings` | 是 | 读取（凭据项返回掩码）/ 保存设置 |
| POST | `/api/push/test` | 是 | 发一条测试消息，`{ kind: "first"\|"remind"\|"evening" }`，缺省为 `first` |
| GET | `/api/logs?limit=100` | 是 | 推送记录 |
| GET | `/api/checkins?limit=5000` | 是 | 打卡记录（导出用） |
| POST | `/api/demo` | 是 | 载入 3 行通用示例 |
| POST | `/api/wipe` | 是 | 清空全部数据 |

鉴权方式：请求头 `x-admin-token: 你的口令` 或查询参数 `?token=你的口令`。未设置口令时一律放行。

## 常见问题

**怎么更新到新版本**

`docker compose pull && docker compose up -d`，数据在 `./data` 不受影响。
compose 里没设 `pull_policy: always`，因为那样断网重启会拉取失败、容器直接起不来；
这是个每天要推十几次的提醒服务，宁可用旧镜像也要让它活着。

**升级后要手动改数据库吗**

不用。启动时会逐项检查并自动补列：`plans` 缺 `weekdays` 就补（老数据默认「每天」）、
缺 `push_on` 就补（默认开启推送）、`push_logs` 缺 `kind` 就补（老日志记为 `first`）。
打卡记录与历史推送记录原样保留，从旧版本升上来行为跟以前一致。

**怎么让几个人都收到**

三条路，选一条：

- PushPlus（最省事）：每人关注公众号拿一个 token，逗号隔开填同一个输入框。苹果安卓通吃。
- 企业微信群机器人（群消息）：收消息的人进同一个企业微信团队，建内部群加机器人，填 Webhook。
  普通微信群加不了机器人，这是微信侧的限制，绕不过。
- Server 酱（各收各的）：每人注册一个 SendKey，逗号隔开填同一个输入框，注意免费额度只有每天 5 条。

**催办没收到**

按顺序查：① 那条计划的「推送」是否勾选；②「超时催办」是否为 0（0 表示关闭）；
③ 到催办时间时这条是否已经打过卡，打过就不催；④「推送日志」里有没有 `催办` 类型的记录，
有记录但失败，看详情列的报错。可以先用「发送催办样张」确认通道本身通不通。

**晚间总结没收到**

按顺序查：①「晚间总结」是否勾上；② 总开关是否开着（关掉后提醒、催办、总结全都不发）；
③ 当天是否有要执行的项目，全部停用或都按星期休息时不会发；④ 时间是否已过；
⑤「推送日志」里是否有 `总结` 类型的记录。可以先用「发送总结样张」确认通道。

**收不到推送**

先点「发送测试推送」看返回详情，再查「推送日志」。按渠道看错误码：

- PushPlus：`905` 是没实名认证，`900` 是当天额度耗尽或账号被限，`code=200` 只代表请求收到，
  真正送达要到公众号里查推送记录
- Server 酱：`code` 非 0 时看 message，常见是 SendKey 填错或当日 5 条免费用完
- 企业微信：`93000` / `93001` 是 Webhook 地址错，复制时多带了空格或换行

另外确认设备所在网络能访问对应域名（`www.pushplus.plus` / `sctapi.ftqq.com` / `qyapi.weixin.qq.com`）。

**时间对不上**
容器内 `TZ` 必须是 `Asia/Shanghai`（compose 文件已设置）。宿主机时区不影响容器。

**错过的那条会补发吗**
会，但只在 `GRACE_MINUTES`（默认 5 分钟）窗口内。超窗口不补，避免半夜收到过时提醒。

**端口冲突**
改 `docker-compose.yml` 里的 `8787:8787` 左侧端口，或本地运行时设 `PORT`。

**alpine 镜像里 `node:sqlite` 报错**
极少数情况下官方 alpine 构建缺少内置 sqlite，把 `Dockerfile` 首行改成 `FROM node:22-slim` 即可。

**忘记管理口令**
停服务后删掉 `settings` 表里那一条记录（其他配置不受影响）：
`sqlite3 data/app.db "DELETE FROM settings WHERE k='admin_token';"`，或直接清空数据重录。

**镜像拉下来跑不起来，报 `exec format error`**
架构不匹配。在 arm64 机器（如 Apple Silicon Mac）上构建的单架构镜像，无法在 x86_64 设备上运行。
本项目的 CI 已构建 `linux/amd64` + `linux/arm64` 双架构；若自己手动构建，请用：

```bash
docker buildx build --platform linux/amd64,linux/arm64 -t pill-reminder:latest .
```

或者直接在目标设备上用 `docker compose up -d --build` 本地构建，天然匹配本机架构。

**GHCR 拉取超时**
国内访问 `ghcr.io` 不稳定属于常态，不是仓库问题。改用方式一本地构建即可；
也可以把镜像同步到阿里云 ACR 等国内仓库再拉。
